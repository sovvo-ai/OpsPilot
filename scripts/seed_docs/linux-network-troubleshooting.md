# Linux 网络故障排查

## 1. 连通性分层排查

### 链路与网卡

先确认网卡是否 up，用 `ip link` 查看状态，出现 `state DOWN` 说明链路层未就绪。

### IP 与路由

用 `ip addr` 确认地址是否配置正确，用 `ip route` 确认默认网关是否存在。

缺少默认路由时，内网可达但访问公网会失败，表现为长时间等待后超时。

### 端口监听

服务起不来时先确认是否真的在监听，用 `ss -lntp` 查看监听地址与进程。

监听在 `127.0.0.1` 时只有本机可访问，容器或外部访问必须监听 `0.0.0.0`。

## 2. DNS 解析

`ping` 域名失败但 `ping` IP 成功，通常是 DNS 问题。

用 `nslookup` 或 `dig` 单独验证解析结果，再用 `cat /etc/resolv.conf` 确认 nameserver 配置。

容器内 DNS 问题优先怀疑宿主机与集群 DNS 服务的连通性。

## 3. 常见错误码含义

`Connection refused` 表示目标端口没有进程监听，或防火墙主动拒绝，问题在服务端。

`Connection timed out` 表示报文被丢弃，常见于防火墙丢包、安全组未放行、路由不可达。

`No route to host` 表示链路层不可达，通常是同网段内主机不存在或 ARP 失败。

理解这三个错误的区别，可以快速把问题范围从"服务挂了"收敛到"网络不通"或"配置错误"。
