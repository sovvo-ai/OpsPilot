# 线上服务日志规范

## 1. 日志级别约定

ERROR 只用于需要人工介入的失败，例如请求无法完成、数据不一致、依赖不可用。

WARN 用于可自愈的异常，例如重试成功、降级返回、连接池短暂耗尽。

INFO 记录关键业务动作，每个请求一条汇总即可，不要在每个函数入口都打日志。

DEBUG 默认关闭，只在定位问题时临时开启。

## 2. 结构化日志字段

推荐字段：时间戳、级别、服务名、实例标识、`request_id`、错误码、耗时、结果状态。

耗时字段统一用毫秒整数，避免混用秒与微秒。

错误码必须是有限枚举，禁止把异常堆栈直接当错误码使用。

## 3. 错误码与 request_id 规范

`request_id` 由网关生成并透传到下游，全链路保持一致，便于串联同一请求的所有日志。

日志中禁止输出密钥、令牌、完整身份证号等敏感信息；确需定位时只记录哈希前缀。

错误日志必须包含错误码与 `request_id` 两个字段，否则排查时无法与监控告警对齐。
