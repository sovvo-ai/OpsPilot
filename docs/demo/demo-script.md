# OpsPilot 3 分钟演示分镜

> **用途**：求职/评审时 3 分钟内讲清楚"这是什么、跑起来什么样、凭什么可信"。
> **纪律**：所有输出必须来自**真实运行**，禁摆拍、禁预置结果。
> **两版录像**：浏览器版 `demo.gif`（推荐，真前端）＋ 终端/API 版 `demo-api.gif`。
> 录制脚本：`scripts/s9_demo_record.py`（浏览器，Playwright + 系统 Edge）／
> `scripts/demo_record.py`（终端）。页面文本证据见 `docs/testing/s9-ui-smoke.md`。
> **演示客户端**：一律 Python `httpx`（UTF-8）；**禁止 Windows shell `curl`**（中文经 shell 传参会被转义破坏，见 `test-plan` G7）。

总时长分配：`0:00–0:20` 定位 → `0:20–1:00` 上传与检索 → `1:00–1:50` 带工具排查 → `1:50–2:30` 拒答与澄清 → `2:30–3:00` 轨迹与证据链。

## 0:20–1:00 · 上传 → 切片 → 引用可展开

**动作**（终端）：

```bash
# 上传 5 篇运维文档（Nginx/MySQL/K8s/网络/可观测性）
for f in scripts/seed_docs/*.md; do ... POST /api/v1/documents ...; done
# 轮询至 completed
GET /api/v1/documents/{doc_id}   →  ingest_status=completed, chunk_count=2
```

**说什么**：
- "摄取是**两阶段发布**：切片先 `visible=false` 写入，CAS 成功后才置 `visible=true` ——
  所以**没完成的文档永远不会被检索到**，不存在半成品污染。"

**提问**（kb_qa 路径）：

```python
POST /api/v1/sessions/{sid}/messages
{"question": "Nginx 的 502 和 504 分别代表什么？"}
```

**展示**：回答 + 引用列表（`chunk_id` / `doc_title` / `score`），指出**每句结论后的 `[n]` 都指向真实片段**。

## 1:00–1:50 · 带日志排查 → 工具真的被调用

**动作**：贴一段 `connection refused` 日志 + 模糊问句：

```python
{"question": "帮我看看这段日志",
 "attach_log": "2026-10-23 10:00:01 ERROR dial tcp 10.0.0.1:3306: connect: connection refused\n..."}
```

**展示轨迹**（这是**卖点**，一定要展开）：

```
node_path = [router, retrieval, troubleshoot, evidence, final]
tool_calls:
  analyze_error_log     ok   0ms   sha256:cd22115e...
  check_port_conflict   ok   0ms   sha256:78bc4c3e...
```

**说什么**：
- "注意路由 —— 用户只说了『帮我看看这段日志』，**没提任何错误特征**。
  系统是**看附件内容**才判定为排障的。"
- "工具输出**只存摘要**（`args_digest`），不存原始入参 —— 日志可能含敏感信息。"
- "回答里 `[工具]` 标注的是工具结论，`[n]` 标注的是知识库片段，**两类证据分开标**。"

**对照演示（可选，30s）**：端口冲突场景

```python
{"question": "8080 nginx 正在监听\n8080 java 也在用，是不是端口冲突？"}
→ "工具检测已发现 1 处端口冲突[工具]"
```

> 讲点：这里曾经有个真缺陷 —— 端口提取用 `set` 去重，把"两行同端口"压成一条，
> 于是**永远报不出冲突**。已修，回归用例是"两行同端口 → conflicts 非空"。

## 1:50–2:30 · 拒答与澄清（**最容易被忽略、但最能体现严谨**）

**动作 A：知识库确实没有的问题**

```python
{"question": "公司差旅报销流程是什么？"}
→ answer_type = refusal
```

**实际输出**（真实运行原文，浏览器版录像 1:50 处可见）：

```
未在知识库中找到与该问题相关的资料（检索到的内容均低于相似度阈值）。

以下是我检索到的最高分片段（分数 0.289，低于阈值），你可以判断是否是文档缺失：
> 来源：observability-logging
> # 线上服务日志规范  ## 1. 日志级别约定  ERROR 只用于需要人工介入的失败…
```

> ⚠️ 这段"最高分片段"曾经**拿不到**：检索层把低于阈值的全部过滤掉 → `chunks` 为空 →
> 拒答只能干说"未找到"，PRD §7.4 的硬要求形同虚设。修复是让检索层额外带回一个
> **阈值下的最高分探针**（`probe=true`），只服务拒答展示、不参与作答。

**说什么**："拒答时不是干说『不知道』—— 它把最高分片段和分数摆出来，让你判断是**文档缺失**还是**没问对**。"

**动作 B：追问脱离上下文**

```python
{"question": "它起不来了怎么办？"}     # 新会话，无上文
→ answer_type = clarify
→ "信息不足，我需要再确认一下才能回答。请补充以下任一信息：1. 具体服务/组件名… 2. 错误日志片段… 3. 端口号与现象…"
```

**说什么**：
- "这句里有个『起不来』—— 早期实现会因为这个词直接进排障，然后**模型自己猜一个指代对象**开始生成。
  这违反 PRD §7.4『追问脱离上下文 → 给 2~3 个候选，**不猜**』。"
- "现在：**裸指代硬否决**为 clarify，零模型调用。有上文时（`那它怎么配？`）才走正常回答 + 查询改写。"
- "对照：`8080 起不来了怎么办？` —— 有端口号就**该**进排障，不会被误拦。"

## 2:30–3:00 · 证据链与评测可信度

**动作**：展开 `GET /api/v1/runs/{run_id}` 的完整字段。

```
route=kb_qa  node_path=[router, retrieval, evidence, final]
retrieval_top_score=0.779     retrieved_chunk_ids=5 个
rewritten_query=None          duration_ms=1983
```

**说什么**：
- "轨迹里存的是**完整 Top-K 检索集**，不只有被引用的那几条 —— 所以 Recall 可以复算，不是自证。"
- "评测 35 题，Recall@5 **1.000**、MRR@5 **0.812**、多轮保持率 **1.000**（A/B 配对法）、
  引用 ID 有效率 **100%**（硬线）、引用内容支持率 **0.950**、任务成功率 **0.950**。"
- "干净环境 `down -v → up -d → 冒烟通过` **28.4 秒**。"

**⭐ 加分点（一定要说，比满分更有说服力）**：

> "支持率不是 1.000，是 **0.950** —— 因为**人工复核抓到了 1 条『引用越界』**：
> 模型把片段之外的通用知识挂在了真实有效的 KB 引用号下。
>
> 关键在于**机器指标全都抓不到它**：检索层确实命中了相关片段（Recall 正常），
> 引用 ID 也真实有效（硬件校验全过）—— 只有人工读语义才发现那段内容**不支撑**那句结论。
>
> 我没有为了好看去调数据集或调阈值，而是把它记进校准日志、排进修复项。
> 这也正是把『引用 ID 有效率』和『引用内容支持率』**分成两个指标**的原因 ——
> 合并成一个数会掩盖『引用都存在但都不支持』这种最危险的情况。"

**收尾一句**：
> "这套东西的设计原则只有一条：**宁可说不知道，也不说没依据的话** —— 而且这句话在代码里是**可验收**的，不是口号。
> 连『评测本身有没有用』这件事，我也是用实证回答的：它真的抓出过一条我原以为没问题的引用。"
