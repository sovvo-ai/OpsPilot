## ① 检索质量：把"召回"做成可复算，而不是自证

**问题**：RAG 最常见的自我欺骗是"拿被引用的片段算召回" —— 引用本身是模型选的，
用它算 Recall 必然虚高（我第一版就踩了这个坑：`agent_runs` 只存被引用切片）。

**做法**：
- 落库**完整 Top-K 检索集**（`retrieved_chunk_ids`，迁移 `0002`），Recall 按 gold 子串在**整个 Top-5** 内匹配；
- 多轮保持率用 **A/B 配对法**（`ΣRecall_A / ΣRecall_B`），非可比样本 >40% 时**直接输出 `NOT RUN`**，不编数字；
- 报告含 git commit、逐题结果、模型与参数（`top_k`/`min_score`/`ef_search`），可复算。

**量化结果**：35 题评测集 **Recall@5 = 1.000**、**MRR@5 = 0.812**、**多轮保持率 = 1.000**（阈值 ≥0.90）；
kb_qa 延迟 **P95 = 7.3s**（阈值 ≤8s）。**未跑的两项标 `NOT RUN`，不填推算值。**

## ② 抗幻觉：拒答与澄清是**代码路径**，不是"请模型别编"

**问题**：早期实现的三个真实缺陷（都是我在验收里抓出来的，不是设想）：
裸短语"起不来"单独触发排障 → 模型**自己猜**指代对象开答；
端口提取用 `set` 去重 → "两行同端口"被压成一条 → **永远报不出冲突**；
`Final` 非直通时重新生成 → troubleshoot 已产出的**工具证据被丢弃**。

**做法**：
- 图上把证据闸门做成**确定性节点**：`Evidence Checker` 拦"引用存在但不支撑结论"；
  `Refuse` / `Smalltalk` 是纯代码终止节点，**零模型调用**；
- 路由层区分**强特征**（error/exception… 自身即证据）与**弱特征**（起不来/挂了… 必须伴随其他线索）；
  **裸指代硬否决**为 clarify（PRD §7.4："给 2~3 个候选，不猜"）；
- **引用 ID 有效率设为 100% 硬线且独立于七项指标** —— 它测"引用是否存在"，与"引用是否支撑"分开统计，
  避免合并后掩盖"引用都存在但都不支持"这种最危险的情况。

**量化结果**：拒答正确率 **0.875 → 1.000**（D1 修复后）、过度拒答率 **0.000**、
引用 ID 有效率 **100%**（硬线全通过）、**引用内容支持率 0.950 / 任务成功率 0.950**。

> **⭐ 这 0.950 比 1.000 更有说服力**：人工复核 5 条时抓到 1 条**引用越界**（`m001`）——
> 模型把片段外的通用知识挂在**真实有效**的 KB 引用号下。**机器指标全都抓不到它**
> （检索有命中、引用 ID 校验全过），只有人工读语义才发现内容不支撑。
> 我没为此调数据集或调阈值，而是记进校准日志 + 排进修复项 —— 这证明评测体系**真的在起作用**，
> 也正好解释了为什么"引用 ID 有效率"和"引用内容支持率"必须是两个指标。

## ③ 工程严谨：一致性不靠"应该没问题"，靠状态机 + 断言

**问题**：摄取是异步的，最危险的状态是"记录已写、向量没落"或"文件已删、向量还在" ——
这类问题单测很难覆盖，往往等线上才炸。

**做法**：
- **两阶段发布**：切片先 `visible=false` 写入，**CAS 成功后才**置 `visible=true` 并推进任务状态 →
  未完成文档**永不参与检索**；删除后 Python 迟到的结果 CAS 失败即丢弃，不留残留向量；
- 用 **SQL 不变量**断言一致性（A14/A15），不信任接口返回值自证；
- 并发上传同内容的竞态：唯一约束 + 捕获 `23505` 兜底 ——
  这是我在 §9.4 异常矩阵里**实测抓到的 500 缺陷**（8 轮压测 1 轮异常 → 修后 12 轮 0 异常）；
- 全局测试约定 G1~G7 全部来自**实测教训**（含"含中文的验收一律 Python httpx，禁 Windows shell curl"）。

**量化结果**：§9.4 异常矩阵 **18/18 通过**；干净环境 `down -v → up -d → 冒烟通过` **28.4 秒**（目标 ≤5 分钟）；
后端 `go vet` / `go test` 全绿、Python **191 项测试通过**。
