# ADR-0001：引入生成后独立审查者（Critic Agent）

| 项 | 值 |
|---|---|
| 状态 | **待外部审查**（实现方不得自行置为 Accepted —— 计划书附录维护规则 4） |
| 日期 | 2026-10-27 |
| 决策者 | 实现方提案，外部审查裁定 |
| 上游 | `docs/prd/PRD-delta-v1.1.md` §1、§2、§4；`docs/testing/v3_residual_notes.md` 残留 1 |
| 影响面 | `ai-service/app/graph/`（图结构、state、预算）、`backend/migrations/`（trace 表）、前端轨迹抽屉 |

---

## 1. 决策

在 `final` 节点之后、`END` 之前，插入一个**独立的 critic 节点**，对"结论句 × 其声明的片段原文"做**逐句配对审查**，并按其裁决执行三态处置。

**这是拓扑选择，不是实现细节。** 备选方案与否定理由见 §2。

---

## 2. 备选方案对比

### 2.1 方案 A：生成后独立审查者（本 ADR 选择）

```
final ──► critic ──► END        （critic 条件启用）
```

critic 收到的是**已生成的答案 + 检索片段**，在**全新上下文**里独立判断每句话是否被其引用的片段支撑。

### 2.2 方案 B：自审（同一节点内让模型重读自己的输出）

```
final（生成 + 自审一体化）──► END
```

在同一个 LLM 调用或同一段 prompt 里追加"现在检查你上面写的内容是否有依据"。

**否定理由（核心论证）**：

| 问题 | 说明 |
|---|---|
| **自证盲区** | 生成时的上下文包含完整的思考路径与措辞动机。模型倾向于**为自己的选择辩护**（"我写这句是因为片段里提到过 X"），即使 X 实际不在片段中。 |
| **注意力锚定** | 同一个上下文里，模型对"我刚写过的东西"的注意力权重高于"片段原文"。这正是越界产生的原因，自审无法跳出该分布。 |
| **prompt 纪律已被证伪** | `chat.py` 的规则 1（引用纪律）与规则 3（编号必须与主题匹配）**就是**一种"事前自审提示"。实测 5/5 采样仍有越界（`v3_residual_notes.md` 第 7–13 行）。**继续在同一个 prompt 里加规则，属于已被证伪的路径**。 |
| **无法逐句归因** | 自审拿不到"这句话 声明引用的是哪一条片段"的显式配对，只能整体判断"这份答案看起来靠不靠谱"。 |

> **关键论证**：越界的根因是**生成时的注意力**（模型在写结论时把自身知识带进来了）。
> 要检测它，必须让判断者处于**没有该注意力偏向的上下文**里。
> 这就是"生成与审查不共享上下文/提示词"的必要性 —— 不是洁癖，是**破自证盲区的手段**。

### 2.3 方案 C：规则层加强（扩大 `detect_citation_overreach` 的字典/权重）

**否定理由**：

- 现有检测器基于"技术标识符是否出现在片段原文"，**当前已经 0/5 干净** —— 说明它抓得到信号，
  问题在于它**只观测不阻断**。
- 但直接把"检测到就删引用"作为处置，会发生**误删**：一句合法结论可能因为
  同义改写（片段写"存活探针"，答案写"livenessProbe"）被判越界。
  实测 `a3b_user_review_v3.md` q001 的判定备注就写着"（livenessProbe）是同义注记，未引入片段外事实"——
  **这种句不该被删**。
- 规则层无法区分"同义注记"与"引入片段外事实"，需要语义判断 → 需要模型。

**结论**：规则层保留为**廉价前置过滤器**（critic 只审规则层命中的句子，降低 critic 输入量），
但**不能作为唯一处置层**。

## 3. 输入契约（数据最小化，防越界扩散）

### 3.1 critic 的输入**只允许**这两项

| 字段 | 内容 |
|---|---|
| `claim` | 单句结论（从 `final_text` 按句切分，仅取**含 `[n]` 标记的句子**） |
| `pairs` | 该句声明引用的编号 + **对应片段的完整原文** |

```json
{
  "claim": "启动慢的应用应改用 startupProbe 提供启动宽限期[1]。",
  "pairs": [
    {"index": 1, "doc_title": "k8s-pod-troubleshooting",
     "source": "常见错误是把耗时的启动检查放进 livenessProbe，导致应用还没启动完就被反复重启。启动慢的应用应使用 startupProbe 保护。"}
  ]
}
```

### 3.2 禁止注入的内容（硬约束）

| 禁止项 | 理由 |
|---|---|
| `question`（用户原始问题） | **不是必需**，且会引入"这答案整体是否切题"的干扰。critic 的职责是"这句话是否被该片段支撑"，不是"这答案好不好" |
| `history`（对话历史） | 同上，且会带来指代消解问题 |
| 生成过程的中间产物（`draft_answer`、`check_result`、router 推理） | **这是破自证盲区的关键** —— critic 一旦看到"生成时怎么想的"，就重新陷入方案 B 的锚定 |
| 其余片段的全文 | 只给**该句声明的**那几条。给全量会让 critic 做"帮它找依据"而不是"核对声明" |

> **实现要求**：critic 应为**独立的一次 LLM 调用**，prompt 里**不包含**上述任何字段。
> 该约束须有测试断言（`test_critic_input_minimization`）。

### 3.3 为什么"只审含 `[n]` 的句子"

- 无 `[n]` 的句子**没有声明引用**，即使含片段外内容也不构成"引用越界"
  （PRD FR-18③ 允许标注"模型通用知识，无 KB 出处"）。
- 这样把 critic 输入量压到**答案中最小的关键子集**，直接服务于 §4 的预算约束。

## 4. 输出 Schema

### 4.1 严格 schema（JSON mode）

```json
{
  "verdicts": [
    {
      "claim_index": 0,
      "verdict": "supported",
      "reason": "结论与片段首句逐字对应"
    },
    {
      "claim_index": 1,
      "verdict": "unsupported",
      "reason": "片段来自《Linux 网络故障排查》，全文不含 livenessProbe 内容，无法支撑探针重启结论"
    },
    {
      "claim_index": 2,
      "verdict": "needs_downgrade_label",
      "reason": "片段提到 startupProbe 保护启动慢应用，但未给出具体参数值，参数建议属片段外"
    }
  ]
}
```

### 4.2 三态定义（**互斥且穷尽**）

| verdict | 语义 | 判定标准 |
|---|---|---|
| `supported` | 该片段**确实支撑**该结论 | 结论的事实要素能从片段原文直接读出（允许同义改写，如"存活探针"↔`livenessProbe`） |
| `unsupported` | 该片段**完全不支撑**该结论 | 片段主题与结论对象无关（如用《Linux 网络排查》支撑探针结论），或结论的核心事实在片段中不存在 |
| `needs_downgrade_label` | 结论**部分**有依据，但含片段外内容 | 结论主体有依据，但附带了片段未给出的**具体参数/数值/机制** |

> **三态而非二态的理由**：二态（支持/不支持）会在"主体对、细节超出"的情况下二选一错。
> 见 `a3b_user_review_v3.md` q001：结论是片段原句，括号里加了 `(livenessProbe)` 同义注记 ——
> 判 `unsupported` 会误删正确内容；判 `supported` 又放过了一个片段外的词。`needs_downgrade_label` 才是准确落点。

### 4.3 处置策略（全部动作进 trace，**禁止静默修改**）

| verdict | 处置 | 用户可见结果 |
|---|---|---|
| `supported` | **不改动** | 原样保留，含 `[n]` |
| `unsupported` | **剥离该句**（整句删除），同时移除该句独占的引用 | 该句不出现；若因此引用列表变空，走 `final` 的兜底归因（`final.py:262`） |
| `needs_downgrade_label` | **改标**：该句的 `[n]` 移除，句尾追加「（模型通用知识，无 KB 出处）」 | 内容保留、引用撤除，用户能看出"这不是文档里的" |

**三条硬规则**：

1. **禁止静默**：每次处置必须写入 `run_steps` 的 critic step（含 `claim` 摘要、`verdict`、`reason`、`action`），
   前端轨迹抽屉可见。
2. **禁止整段重写**：只允许"删除句 / 撤引用+追加标注"，**不允许**让 critic 改写语句内容
   （改写会引入新的、未经审查的文本，等于把审查者变成生成者）。
3. **剥离后必须复核非空**：若剥离导致 `final_text` 为空 → **放弃全部剥离**，回退原文并 `degraded=true`
   （宁可有越界，不可给用户空白答案）。

## 5. 与 `evidence.checker` 的职责边界（避免重复审查）

现有 `evidence` 节点的 checker LLM（`evidence.py:106-110`）也在判断"结论是否被片段支持"。必须划清：

| 维度 | `evidence.checker`（既有） | `critic`（新增） |
|---|---|---|
| 作用对象 | **整份 `draft_answer`** | **单句 claim × 其声明的片段**（配对） |
| 触发时机 | `final` **之前** | `final` **之后** |
| 触发条件 | draft 存在 且 (`not supported` 或 含强断言) | `route=troubleshooting` 或 超长答案（见 delta §3.1） |
| 输出粒度 | 布尔 `supported` + `method` | 每句一个 verdict + reason |
| 处置能力 | **无**（只把结果传给 final 做 prompt 提示） | **有**（三态处置，见 §4.3） |
| 失败影响 | 退回纯规则，不阻断 | 跳过 critic，`degraded=true`，**原样输出** |

**互补性论证**：checker 管"这份草稿整体靠不靠谱"（粗粒度、生成前），critic 管"每一句是否被它自己声明的片段支撑"（细粒度、生成后且可处置）。
**二者的重叠部分是"支持性判断"，但作用粒度与处置能力不同** —— 不构成重复。

**预算冲突处置**：见 delta §4.2 方案 C —— 若 SPIKE 证明预算不足，**让二者互斥**
（`checker` 已调用则跳过 `critic`），因为 checker 已在粗粒度上做过一次同类判断，
被它放行的草稿再上 critic 的边际收益低于一次独立审查的成本。

## 6. 后果

### 6.1 正面

- 越界从"仅可观测"变为"可处置"，直接对应 `v3_residual_notes.md` 残留 1 的收口要求。
- 审查者上下文隔离 → 破自证盲区，这是 prompt 层纪律（已被 5/5 采样证伪）做不到的。
- 全动作进 trace → 可回归、可复核，不是黑盒。

### 6.2 负面（必须承认）

| 负面 | 量级 | 缓解 |
|---|---|---|
| **多一次 LLM 调用** | troubleshoot 最坏路径 5→6，**顶满 `MAX_LLM_CALLS`** | 只审含 `[n]` 的句子；SPIKE 定预算方案 |
| **多一次网络往返** | troubleshoot P95 会增加（赌注 B4 保证 ≤25s） | 该路径 P95 阈值 25s，余量比 kb_qa 的 8s 宽 |
| **可能误删正确内容** | 取决于 critic 准确率 | 三态而非二态；剥离后非空校验；`needs_downgrade_label` 保留内容 |
| **引入新的失败模式** | critic 超时/格式错误 | 失败即跳过 + `degraded=true`，**绝不阻断答案**（与 checker 同策略） |

### 6.3 明确不承诺

- **不承诺 overreach 归零是永久性的**。B1 只保证"本次评测的 35 题 + 专项集上 0 处"。
  模型行为会漂移，**该赌注需在后续每次评测复验**。
- **不承诺替代人工复核**。critic 是机器审查者，A3b 的人工抽样（≥90%）**仍然保留**。
